This program keeps track of simulated temperature readings from a device. It keeps a list of readings, takes in new valid readings, and sorts each one into NORMAL, WARNING, or CRITICAL. It also displays a numerical summary along with an overall monitoring status. This is a CPP102 Week 17 integrative project that brings together lists, loops, selection, and functions. ## Features - View all stored temperature readings - Add a new reading (whole numbers from 0 to 100 only) - Classify every reading (below 30 °C NORMAL, 30 to 35 °C WARNING, above 35 °C CRITICAL) - Generate a numerical summary: count, total, average, minimum, maximum, category counts and percentages, and overall status - Reject invalid menu choices and invalid readings (empty, non-numeric, below 0, above 100) without crashing ## Requirements - Python 3 (no external packages) ## How to Run 1. Open a terminal in the Week17 folder. 2. Enter: `python device_monitor.py` (On macOS or Linux, enter: `python3 device_monitor.py`) ## Sample Output ``` SIMULATED DEVICE MONITORING SYSTEM ---------------------------------- [1] View Readings [2] Add Reading [3] Classify Readings [4] Generate Summary [5] Exit Enter choice: 4 MONITORING SUMMARY ------------------ Number of readings : 5 Total of readings : 160 Average temperature : 32.00 °C Minimum temperature : 28 °C Maximum temperature : 37 °C NORMAL : 2 (40.00%) WARNING : 2 (40.00%) CRITICAL : 1 (20.00%) Overall Status: ATTENTION REQUIRED ``` ## Test Cases I ran 15 tests. 15 passed and 0 failed. Complete details can be found in [test_cases.md](test_cases.md). ## Known Limitations - Readings are lost once the program closes (no file handling). - Once added, readings cannot be edited or deleted. - The 0 to 100 limits and the 30 and 35 °C thresholds apply only to this classroom simulation. They are not actual device-safety standards. ## Reflection The hardest part was making the program modular, since I had to decide what each function should do and pass data through parameters and return values rather than using global variables. I was most careful with the boundary values 30 and 35. Using `&lt;=` 35 in `classify_reading()` keeps both 30 and 35 as WARNING, and I tested them directly (TC06 and TC07). Writing the minimum and maximum loops myself taught me to start from the first reading rather than 0, since starting from 0 would always return 0 as the minimum. Next, I would save the readings to a file so they are not lost when the program closes, and add a way to edit or delete a reading.
